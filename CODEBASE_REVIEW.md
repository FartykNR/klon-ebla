# Обзор кода проекта klon-ebla

## 1) Технологический стек
- **Backend:** Flask + Flask-SQLAlchemy.
- **База данных:** SQLite по умолчанию (`sqlite:///database.db`) c возможностью подмены через `DATABASE_URL`.
- **Frontend:** Jinja2 шаблоны + Bootstrap 5 + кастомный CSS.
- **Хранение медиа:** локальная директория `uploads/`.

## 2) Архитектура
- `app.py` содержит маршруты, конфигурацию Flask и инициализацию БД.
- `models.py` содержит модель `Post`.
- Шаблоны:
  - `templates/index.html` — лента постов;
  - `templates/new_post.html` — форма создания;
  - `templates/post.html` — страница конкретного поста.
- Статика: `static/style.css`.

## 3) Основной пользовательский поток
1. Пользователь открывает `/` и видит список постов, отсортированный по дате или лайкам.
2. На `/new` создаёт пост с заголовком, текстом и (опционально) изображением.
3. Файл сохраняется в `uploads/`, а в БД записывается имя файла.
4. На `/post/<id>` пользователь может увеличить счётчики лайков и комментариев.

## 4) Что в коде уже хорошо
- Простая и понятная структура для маленького Flask-проекта.
- Есть базовое логирование критического сценария создания поста.
- Используется `secure_filename` при сохранении файлов.
- Есть fallback-конфигурация БД для локального запуска.

## 5) Точки внимания и риски
- `SECRET_KEY` захардкожен в коде.
- Нет ограничений размера и валидации типа загружаемого файла на backend-уровне.
- Директория `uploads/` не создаётся явно при старте приложения.
- Использование `|safe` для пользовательского контента может привести к XSS.
- Нет CSRF-защиты для POST-форм.
- Счётчик «комментариев» пока технический (`+1`), без сущности комментария.
- Логика, маршруты и инициализация находятся в одном файле (`app.py`), что затруднит масштабирование.

## 6) Рекомендуемый план улучшений
### Краткосрочно
- Перенести `SECRET_KEY` в переменные окружения.
- Добавить `MAX_CONTENT_LENGTH` (например, 10 MB) и проверку расширений (`jpg`, `png`, `gif`, `webp`).
- Создавать `UPLOAD_FOLDER` при старте (`os.makedirs(..., exist_ok=True)`).
- Убрать `|safe` для пользовательского текста или добавить санитайзер.

### Среднесрочно
- Подключить Flask-WTF и CSRF.
- Разделить код по модулям (`routes/`, `services/`, `config.py`) или перейти на app factory.
- Добавить тесты для ключевых маршрутов (`/`, `/new`, `/post/<id>`).

### Долгосрочно
- Добавить полноценные комментарии (отдельная модель).
- Вынести хранение файлов в S3-совместимое хранилище для production.
- Добавить авторизацию и права доступа к действиям.

## 7) Как запускать локально
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

## 8) Мини-чеклист перед production
- [ ] `SECRET_KEY` только из окружения.
- [ ] CSRF включён.
- [ ] Ограничения/валидация загрузок включены.
- [ ] XSS-риски закрыты.
- [ ] Логи не содержат чувствительных данных.
- [ ] DEBUG выключен.
